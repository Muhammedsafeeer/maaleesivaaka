# `src/components` — Shared UI

Components used by **two or more features**. Anything belonging to a single feature lives
in `src/features/<feature>/components/` instead.

```
components/
├── ui/          shadcn/ui primitives. Generated by `pnpm dlx shadcn@latest add <name>`.
├── forms/       Reusable field wrappers, form layout, submit buttons with pending state.
├── tables/      Data table shell, pagination, sorting, empty and loading states.
└── dashboard/   Stat cards, section headers, page shells shared by admin and judge.
```

## `ui/` is generated, but it is yours

shadcn/ui copies source into the repository rather than installing a package. Editing
these files is expected and supported. Re-running `add` for an existing component will
overwrite your changes, so prefer wrapping in `forms/` or `dashboard/` over modifying a
primitive directly.

Before creating any component, check whether a primitive already exists —
`docs/agents.md`: *"Do not create duplicate UI components."*

## Rules

- Under roughly 250 lines. Split anything larger.
- One responsibility.
- **No business logic.** A component may format a value for display; it may not decide
  what the value means. Ranking, averaging and points conversion live in `lib/services/`.
- Accessible by default: real `<label>`s, keyboard navigation, focus management, ARIA
  where semantics need help.
- Mobile-first. Judges score on phones; the audience view runs on a projector.
